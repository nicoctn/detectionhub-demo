01 / Analyst workflow

From reference to decision

The harness brings reference content, an analyst’s tuned rules, conversion, SIEM evidence and CTI into the same workflow. Each component supports a different decision.

Discover

Community Library

Sync public repositories and rule sources, including Sigma, Splunk and Elastic. Search across titles, descriptions and ATT&CK mappings. Import a reference into My Rules with source provenance, its original query and available notes on false positives.

Own and tune

My Rules

Maintain an analyst-curated library with local query variants, required logs, investigation playbooks and version history. Compare local logic with upstream changes, inspect diffs and exchange rule files with GitHub.

Translate and review

Cross-SIEM conversion

Use pySigma through a sigma-cli service for supported Sigma backends, Uncoder IO for supported cross-format translations, or AI-assisted conversion and review. Review mappings and field assumptions before adding the translated query as another implementation.

Investigate

Copilot and coverage analysis

Use the Copilot to retrieve rule implementations, audit rules and analyze ATT&CK coverage. It uses the analyst’s detection profile, including the primary SIEM, available telemetry and known false positives. Coverage analysis separates validated rules, untested implementations, library candidates and gaps.

Classify and test

Decide how the SOC will use it

Artifact type distinguishes a detection rule from a hunting query. SOC usage separately classifies the result as Alert for actionable signals, Monitor for trends, or Hunt for exploration.

Review the rule’s lifecycle, telemetry, test and deployment status separately. Query-test connectors for Splunk, Elastic and Microsoft Sentinel are implemented. Reproducible replay against labeled events is planned.

Reassess

Threat Feed

Collect CTI through RSS, triage it with heuristics and a model, then extract cited behavior and ATT&CK mappings. Compare the evidence with personal rules and community references. Where a gap remains, propose an adaptation or a new rule with telemetry requirements and assumptions for analyst review.

02 / System architecture

How the harness is wired

DetectionHub supplies the blue-team tools, context and workflow. The interactive Copilot uses an agent runtime to choose and call tools. The scheduled Threat Feed drives its own stages and calls the configured model where needed.

Reuse an authenticated runtime

The Claude Agent SDK and Codex App Server paths can reuse the analyst’s signed-in runtime for Copilot and Threat Feed, without a separate model API key in those modes. The provider’s plan and usage limits still apply. API-key and local Ollama modes are separate options.

Claude plan usage · Codex App Server authentication

Separate references from local rules

Keep the upstream rule and the analyst’s tuned variant as distinct records. SQLite FTS5 provides lexical lookup. The profile and retrieved implementations give the model the context for the current investigation.

Make evidence and decisions reviewable

Keep quoted source evidence, prompt versions and per-stage traces alongside proposals. An analyst can inspect, edit or dismiss a proposal before adding it to My Rules for review.

04 / Planned work

Roadmap

Turn CTI findings into reproducible lab tests and use SIEM evidence to decide which detections to keep, tune or investigate.

  1. 01

    Deploy Ludus labs and replay CTI-driven scenarios

    Provision isolated, versioned lab environments with Ludus. Use agents to map CTI findings to approved emulation scenarios and prepare the test plan. Run those scenarios in the lab and capture the telemetry, expected detections and observed results for each test.

  2. 02

    Measure detection quality directly in the SIEM

    Build on the existing query-test connectors to collect per-rule match volume, trends and top triggers over time. Use an agent to inspect samples, explain likely noise and suggest tuning for analyst review. Measure false-positive rates on labeled data and report the proportion of false alerts in reviewed production samples separately.

  3. 03

    Deploy an observability platform

    Integrate Langfuse for model and tool traces, latency, token usage and evaluation results. Correlate these traces with CTI, lab and SIEM runs through a shared run ID. Keep detailed security telemetry in the SIEM and export only the context needed to debug and evaluate the workflow.

  4. 04

    Standardize workflow orchestration with LangGraph

    Use a stateful graph for multi-step CTI-to-lab validation, including checkpoints, retries and approval gates. Keep Claude Agent SDK and Codex App Server behind the existing provider adapters. Start with one workflow and ensure retries cannot launch the same lab run or SIEM job twice.
